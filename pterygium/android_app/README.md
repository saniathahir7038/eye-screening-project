# Eye Screening Android prototype

This combined Android application contains Pterygium, Keratoconus/SmartKC, and Dry Eye/DEDector modules in one modern interface.

See [USAGE.md](USAGE.md) for short, step-by-step instructions.

## Current module status

- **Pterygium:** live on-device screening plus four labelled SLID sample tests.
- **Keratoconus/SmartKC:** live Placido capture with on-device U-Net segmentation and an experimental ring-irregularity result, plus four reference sample tests with PPK, Sim-K, aCLMI and maps.
- **Dry Eye/DEDector:** live Placido-video capture with immediate experimental NIBUT screening, plus a synthetic technical sample for decoding and failure-path testing.

Version `0.5.0-hardware-rc` is an ARM64 hardware-validation build. SmartKC live decisions use a four-sample engineering threshold and do not yet reproduce the complete desktop reconstruction/PPK pipeline. The mobile Dry Eye analyser must still be compared against DEDector using genuine Placido videos. Both modules return an explicit inconclusive result when capture evidence is insufficient.

## Pterygium workflow

- Capture a new eye photograph with the installed camera app or select an existing image.
- Correct JPEG orientation and limit decode size to reduce memory pressure.
- Check minimum resolution, aspect ratio, brightness, contrast and sharpness before inference.
- Conservatively trim a low-detail, skin-coloured lower margin when detected. The full width and top are retained. The preview shows the framed area before the established mask and resize steps.
- Compare full-frame and automatically framed decisions; request a retake if they disagree.
- Apply the Phase 2 top-left neutral mask and resize the image to 224 x 224.
- Run the selected float32 TensorFlow Lite model with a score and a 7 × 7 feature-map output.
- Apply the experimental model threshold `0.16848066449165344`.
- Show `No visible pterygium pattern` or a suspected-pterygium referral message.
- Offer a hidden-by-default research Grad-CAM view after a determinate result. This is an influence map on the processed model input, not a lesion boundary; it does not change the score.

The start screen now includes a five-step test-photo guide: keep the eye horizontal, show the complete iris and visible white on both sides, use even light without strong glare, tap to focus and hold still, then inspect the preview and retake an unsuitable image. These steps improve capture consistency but do not validate the classifier on smartphone photos.

The model score is not a calibrated probability. This is a research screening prototype and does not provide a diagnosis or severity grade. The new head reduced false positives in exploratory web-image testing but missed a labeled pterygium image; smartphone accuracy is unknown.
Automatic framing is a technical adjustment, not calibration of the disease score. The same framing rule now runs in the Python Streamlit interface before being applied in the APK. It was checked against the 408 existing slit-lamp processed images and left all 408 unchanged. Smartphone diagnostic performance remains unvalidated; the camera photo that produced a 0.990 score was not available as a local file for repeat inference.

To compare the Android model's full and auto-framed scores for an original photo stored locally, run `../probe_phone_image.py photo.jpg` in the Phase 2 Python environment. It prints scores without saving a copy of the photo. The current 0.4.0 APK installed and launched on the vivo V2250, but image-level UI testing of its heatmap still needs an unlocked phone.

## Build

Create `local.properties` with the local Android SDK path, select JDK 11, and run:

```powershell
$env:JAVA_HOME = "path/to/jdk11"
$env:GRADLE_USER_HOME = "path/to/gradle-home"
./gradlew.bat testDebugUnitTest assembleDebug
```

The debug APK is generated at `app/build/outputs/apk/debug/app-debug.apk`. Generated builds and APK files are ignored by Git.

## Model provenance

The 0.4.x-experimental `app/src/main/assets/pterygium_model.tflite` and `pterygium_gradcam.bin` are generated by `../export_mobile_heatmap.py` from `../artifacts/domain_adapt_v1/model.keras`. The classifier weights are unchanged; the new TFLite graph also exposes `Conv_1` for Grad-CAM. In 0.4.1, the heatmap fills the preview width without stretching its square model-input image. Their expected SHA-256 values are:

```text
model: 5ac8629dc1f5a0c8a067560a6e8ecd88436aaa30abbcb5c13cb1b6e59523add3
parameters: 09b56fd2080160c6e6e205211cae5bcf8fef4ec8dc0e6be610785c32a5a59b81
```

The new two-output export was checked against Streamlit's Grad-CAM on all 61 SLID validation images. It preserved all 61 decisions; maximum score difference was 0.00000281 and maximum normalized heatmap difference was 0.00478. This tests technical parity, not localization correctness or smartphone diagnostic accuracy. The earlier float16 candidate was rejected because its score difference exceeded the preset limit. The external web-image test partition had already been inspected during model development and is not an independent final test.

The earlier 0.3.0-experimental APK installed and cold-launched on a connected vivo V2250. The user later tested one eye photograph and reported a negative output. Structured on-device replay, physical-device camera, latency, thermal and memory testing remain required before any field study.

## Placido model provenance

`app/src/main/assets/placido_segmentation.ptl` is generated by `smartkc/export_segmentation_mobile.py` from the shared SmartKC/DEDector checkpoint `segment_and_get_center_epoch_557_iter_14.pkl`. The export uses PyTorch 1.13.1 mobile optimization and was checked against the source network with exact output agreement on the validation image.

```text
source checkpoint: 4e5f906d2208e30b52c6a39228c0c14ff76b74698c927901ca4ee3f53d433864
mobile model: 434d0fe7990875f8e5104acc3aff71fbfdc8a764aa40a087e9cd0bcbb063c166
```

The SmartKC and DEDector upstream attribution and licence files remain in their respective source directories.
